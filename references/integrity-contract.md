# integrity-contract.md —— 来源可追溯 / 合成披露 / 强调开关（OneSlide 思路的落地）

这是 slideforge 在"生成内容"层面的纪律。它保证单页**忠实、可信、可追溯**，不把推断/合成伪装成事实。

## 来源分级（每个可见事实都要能溯源）
把每个内容项标为其中一种，并保持稳定的 `source_id`：

| 级别 | 含义 | 处理 |
|---|---|---|
| `user_supplied` | 用户提供的材料/事实 | 原样保留，不篡改 |
| `stable_inference` | 从材料稳定推出 | 与"用户事实"区分开 |
| `calculated` | 由用户数据计算得出 | 保证计算规则/口径一致 |
| `model_augmented` | 模型补全，待确认 | 必须标"模型补全/待确认"或"示例" |
| `external_verified` | 外部核验 | 记录来源 |

## 合成数据与披露
- 合成数字/数据集必须在页底数据来源行写：
  `数据来源：...；合成示例数据，非真实数据`
- 合成定性内容在相邻处标"待确认 / 假设 / 示例"。用户确认某个情景后，它仍是"情景假设"，不足以上升为事实。
- 绝不编造：来源、客户原话、行业基准、法律结论、真实公司业绩。

## 页面结构与备注
- **画面只留**：读者第一眼要懂的结论 + 主证据 + 必要标签/图例。
- **术语、口径、公式、计算方法、专业代号解释** → 放进 PowerPoint 备注（speaker notes），不算删减。
- **页底只允许一行**：`数据来源：...`。方法、口径、样本、期间、限制、建议、合成披露之外的讨论一律
  不放画面；合成披露并入数据来源行。

## 强调默认关闭
- 先分类：`structural_hierarchy`（标题/表头等结构层级）、`readability_pattern`（交替行、共享尺度、
  固定图例）、`business_emphasis`（用户原话/来源支撑的重点）。
- 只有 `business_emphasis` 且带完整 `allowed_emphasis`（含 `target / reason / method / source_ids`）
  才允许强调同一组对象。
- 强调默认方法：`bold=true` + `highlight_fill=true`；`emphasis_border=false`、`emphasis_text_color=false`。
- 禁止：按行号/列号/数组顺序/排名位置/为了视觉平衡自动加粗、随机变色、随机填充、随机描边。
- 允许 `zebra_banding`（两条很接近的中性底色按奇偶行/列交替帮助横读），但不得伴随字重/文字色/边框变化。
- **本地/流程变化不做业务强调**：相邻表格/矩阵/卡片/分栏用同一套细边框，`SHARED_EDGE_STYLE` 保持一致。

## 阻断规则（返回明确状态，不静默降级）
| 情况 | 返回 |
|---|---|
| 超过单页边界（多个主图/主结论/>3 证据主题） | `SINGLE_SLIDE_SCOPE_OVERLOAD`（推荐最强单页焦点） |
| 内容放不下一页 | `SINGLE_SLIDE_FIT_FAIL` |
| 需要真实事实但缺证据且不能诚实补全 | `EVIDENCE_BLOCKED` |
| 地图/行政区/国界/区域分布 | `MAP_POLITICAL_RISK_BLOCKED`（改排序/矩阵/表格/小多图） |
| 内容删除/压缩/移入备注后未重新构图 | `CONTENT_REMOVAL_WITHOUT_REFLOW_FAIL` |
| Builder/运行依赖缺失 | `PPT_RENDERING_BLOCKED`（保留可用 prompt 包，说明原因） |

## 交付前检查清单
1. 恰好一页、画布与 `canvas_profile` 一致。
2. 文字/形状/表格/图表为原生可编辑对象。
3. 画面上只有一行 `数据来源：...`；术语/口径/公式在备注。
4. 无随机强调；同层对象样式一致；相邻容器共边一致。
5. 渲染后人工目测：无重叠、无遮挡、无越界、无文字溢出、配色还原。
6. 说明：哪些是原生可编辑对象，哪些（如有）仍是位图贴入。
